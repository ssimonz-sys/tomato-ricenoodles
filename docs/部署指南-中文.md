# Tomato Ricenoodles 网站部署指南

这份 ZIP 包已经包含英文站和中文站的完整源码。它是**独立的新网站**，不会使用旧的 DaydreamPanda 数据库。

## 一、在本地查看设计

1. 解压项目，进入 `tomato-ricenoodles` 文件夹。
2. 如果 Mac 安装了 Python 3，在终端运行 `python3 -m http.server 8000`。
3. 浏览器打开 `http://localhost:8000/en/?demo=1`（英文版）或 `http://localhost:8000/zh/?demo=1`（中文版）。
4. 预览文章标题是样式示例，真实作品需要你在后台发表；本地静态服务器不会运行 D1 和 API。

## 二、建立新仓库与 Cloudflare Pages

1. 使用你常规的 GitHub 账户创建一个**新仓库**，建议仓库名 `tomato-ricenoodles`。
2. 将解压后 `tomato-ricenoodles` 文件夹**里面的所有内容**上传到新仓库的根目录；如果习惯终端，可以在该文件夹内运行 `bash publish-to-github.sh` 自动完成 Git 提交。特别要保留 `functions/`、`assets/`、`en/`、`zh/`、`lib/`、`schema.sql`。
3. 在 Cloudflare 创建**新的 D1 数据库**，例如 `trn-writings`。在数据库 SQL Console 执行项目根目录 `schema.sql` 的内容。
4. Cloudflare Workers & Pages 中创建新的 Pages 项目，连接刚创建的 GitHub 仓库。构建设置：Framework preset 为 None，Build command 留空，Output directory 填 `.`。
5. 进入新 Pages 项目 Settings / Bindings，添加 D1 binding，变量名必须是 **`DB`**，选择新建的 D1 数据库。
6. 在新 Pages 项目的环境变量/Secrets 中添加秘密 **`ADMIN_PASSWORD`**，值使用随机生成的独立强密码。不要把密码写进源码仓库。
7. 保存设置并重新部署。项目 URL 实际值以 Cloudflare 分配的地址为准，可尝试使用项目名 `tomatoricenoodles`。
8. 打开 `https://你的项目域名/admin/`，输入后台密码，添加文章并发布。

## 三、维护两站

- 英文入口 `/en/`，中文入口 `/zh/`。两站在首页相互切换。
- 文章、分类、专题完全分开，没有逐篇翻译或跨语言文章链接。
- **只使用一个后台 `/admin/`**。写好文章后，在底部的 **Publish to / 发布目标站点** 选择 English Site（英文站）或 中文站，再选择保存为私密草稿或公开发布。
- 修改已发布文章的目标站点时，系统会询问确认，原站对应的文章链接将失效。
- 后台有四种文章分类：Essay / Fiction / Poetry / Note。
- 每篇文章可以设置独立封面链接（HTTPS 图片或者本站 `/assets/graphics/`、`/assets/covers/` 中的图片）。未设置封面的文章列表将自动使用对应站点的抽象/淡彩图形，阅读页保持纯净。
- `site-config.js` 负责两站独立的专题名称、排序、简介、配图和 Medium / Matters 主页链接。
- 英文视觉样式在 `assets/identity-v2.css` 中的 English 部分，中文视觉样式在同文件的 中文站 部分。
- 封面和首页图形都是原创 SVG，存放于 `assets/graphics/`，可以用矢量设计软件编辑。
- 新增专题时给它填写不同语言的 slug 和对应文章，作者后台的 Collections 允许一篇文章绑定多个专题 slug。

## 四、上线前提醒

- 已测试浏览器中的双语设计预览和主要前端入口；尚未在你的真实 Cloudflare Pages + D1 环境完整端到端测试。上线后建议先使用草稿、发布、编辑、删除各一篇测试文章。
- 当前没有从 Medium 或 Matters 抓取文章，也没有自动同步，你需要在后台贴入原文。
- 站点目前以纯前端 JS 获取文章数据；未来如果要做 SEO、文章 RSS 或搜索引擎分享图，可继续增强。
- 严格确保 D1 数据库与成人小说网站互相独立。
