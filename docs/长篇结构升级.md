# 番茄米线：系列 → 书 → 章 → 节

## 为什么采用这种结构

- 系列（Collections）：专题或作品系列；继续使用 `site-config.js` 中已建立的中英文独立系列。
- 书（Books）：一本完整著作，可归属于一个系列，也可独立存在。
- 章（Chapters）：书中的章，支持简介和手动排序。
- 节（Sections）：独立文章正文。每节的正文继续用 Markdown H1 至 H6 细分层级，自动生成节内阅读目录。
- 旧的独立随笔、小说、诗歌仍保存在原来的 `posts` 表中；将文章关联到某章即可成为该章的节，正文不迁移也不会被覆盖。

## 已上线数据库升级（必须手动运行一次）

1. 登录 Cloudflare → D1 → `trn-writings` → Console。
2. 打开 [升级 SQL](https://github.com/ssimonz-sys/tomato-ricenoodles/blob/main/migrations/2026-11-09-hierarchy.sql)。
3. **按分号把 SQL 分成 6 条逐条执行**。Cloudflare Console 如果将代码粘贴成一整行，不要一次复制多个语句，更不要把 `--` 注释粘进 SQL Console。
4. 确认出现 `trn_books`、`trn_chapters`、`trn_section_links` 三个新表。它们与已有的 `posts`、`admin_sessions`、`login_attempts` 共存，不会删除原来的表。
5. 刷新 `/admin/`，打开「系列书架」。

数据库未升级时，后台会提示尚未启用层级功能；原先的文章编辑和网站首页仍能继续使用。

## 使用方法

1. 「系列书架」→「新建书籍」，选择中文站或英文站、归属系列及书籍是否公开。
2. 点击某本书旁的「＋章」，新建一个章节并设置公开状态。
3. 点击章节旁的「＋节」，进入同一个写作编辑器，撰写一节；保存后自动关联。
4. 也可以使用「关联」把一篇已经发表或保存为草稿的文章放进某一章。
5. 在文章正文内部，使用 Markdown 六级标题分别安排节内的标题、段落和子标题。每节都有独立的网址，不需要把整本书挤进一个巨大的正文框。
6. 阅读页按照「系列目录 → 书籍目录 → 章节目录 → 节正文」浏览，并在同一章的节之间提供上一节/下一节导航。

**公开条件：** 书、章、节全部处于「公开／已发布」状态，读者才能通过目录看到它。草稿内容不会由公开目录 API 返回。

**重要：** 章节和书籍的归属信息存储在数据库中；GitHub 仅保存页面源码、API 和升级脚本。进行数据库变更之前，建议先使用 Cloudflare D1 Time Travel 备份或记录恢复点。
